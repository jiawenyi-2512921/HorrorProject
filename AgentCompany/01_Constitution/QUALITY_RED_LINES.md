# 质量红线

任何部门、员工、主脑都不得越过以下红线。

## 构建红线

- 不得在未跑构建时说“构建没问题”。
- Live Coding 阻塞构建时，状态是“验证阻塞”，不是“通过”。
- 缺少模块依赖、include 断链、UHT 风险必须登记。

## 测试红线

- 删除 active 测试必须进入 P0 风险。
- 关闭 legacy 测试不能掩盖断链测试。
- 新增关键逻辑必须有最小回归验证。

## Git 红线

- staged 和 unstaged 对同一文件冲突时禁止提交。
- 不得回滚用户或其他 agent 的改动。
- 不得把无关清理塞进任务交付。

## 运行时红线

- 存档、新游戏、继续游戏、输入恢复、地图切换、资产加载均属于高风险路径。
- 这些路径的改动必须有明确 owner、QA signer、governance signer。

## 沟通红线

- 交接不得只写“看代码”。
- 审查不得只写“LGTM”。
- 风险不得只写“低风险”，必须说明证据。
